# 3단계: geosnap 입력 자료와 변수 정의 (2026-11-24)

만드는 코드: `adapters/seoul_to_geosnap.py` (설계서 6.1에서 "직접 작성하는 유일한 로직")

## 1. 자료 구조
| 항목 | 내용 |
|---|---|

| | `complete_vars`: 7개 변수가 모두 있는 행 |

### 권장 분석 표본
**1,418개 상권 × 2022년 1분기~2026년 1분기 (17분기) = 24,106행.** 이 범위에서는 7개 변수 결측이 0이다.
2021년 분기는 "전년 동기 대비 증가율"을 계산할 비교 대상이 없어서 뺀다.

## 2. 유형화 변수 7개 (설계서 4절)
업종별 값을 평균하지 않고, **개수와 금액을 상권 단위로 먼저 합친 뒤 비율을 다시 계산했다.**

| 변수 | 정의 | 원자료 | 중앙값 | 비고 |
|---|---|---|---|---|
| `sales_per_store` | 점포당 분기 매출액(원) = 매출 합계 ÷ 매출이 추정된 업종의 점포 수 | 추정매출, 점포 | 3,437만 원 | 매출이 없는 업종의 점포는 분모에서 뺌 |
| `sales_yoy` | 전년 동기 대비 매출 증가율(%) | 추정매출 | +2.5% | **극단값 있음** (최대 +444,588%, 전년 매출이 매우 작은 경우) |
| `franchise_share` | 프랜차이즈 점포 비중(%) | 점포 | 16.1% | |
| `open_rate` | 개업률(%) = 개업 점포 수 ÷ 전체 점포 수 × 100 | 점포 | 3.4% | 원자료 정의와 같음(업종 단위 99% 일치 확인). 정수 반올림 없이 계산 |
| `close_rate` | 폐업률(%) = 폐업 점포 수 ÷ 전체 점포 수 × 100 | 점포 | 3.3% | 위와 같음 |
| `young_sales_share` | 20~30대 매출 비중(%) = 20대+30대 매출 ÷ 연령대가 확인된 매출 × 100 | 추정매출(연령대별) | 32.2% | 연령대 미상(법인 등) 매출은 분모에서 뺌 |
| `store_density` | 점포 밀도(개/ha) = 전체 점포 수 ÷ 상권 면적 | 점포, 영역 | 6.7개/ha | |

중앙값은 1,418개 상권의 전체 분기 기준. 원래 개수·금액(`sales`, `stores`, `franchise`, `opened`, `closed`, `young_sales`, `age_sales_total`)도 같은 파일에 들어 있다.

## 3. 성수동 기준 상권 (RQ3)
사용자가 판단을 맡겼고, 기준은 "발표 그림이 효과적인가"였다. 두 층으로 정했다.

| 용도 | 상권 | 이유 |
|---|---|---|
| **경로 기준** (`seongsu_core`) | 성수동카페거리(3110131), 성수역(3120052) | 성수동 하면 떠오르는 두 곳(골목상권 1 + 발달상권 1). 기준이 둘뿐이라 "이 두 곳과 같은 경로를 밟는 상권" 목록과 경로 그림이 한눈에 읽힌다 |
| **지도 강조** (`seongsu_area`) | 성동구 성수·서울숲·뚝섬 일대 13개 상권 | 지도에서는 한 덩어리로 보여야 눈에 띈다. 성수대교남단(강남구)과 뚝섬유원지(광진구)는 이름만 겹쳐서 뺐다 |

## 4. 4단계에 넘기는 사항
- **극단값:** `sales_yoy`의 극단값 때문에 geosnap 기본 표준화(평균·표준편차)를 쓰면 군집이 극단값 몇 개에 끌려간다.
  - geosnap `cluster(scaler=...)`는 scikit-learn 표준화 도구를 그대로 받는다(`docs/api_notes.md`).
  - 예를 들어 중앙값·사분위 범위로 표준화하는 `RobustScaler`를 쓸 수 있다. 새로 구현할 필요가 없다.
- **분기별 표준화:** 설계서 7절 "코로나 회복기 혼입" 대응인 분기별 표준화는 geosnap `pooling="unique"`로 할 수 있다.
- **이웃 기준:** 경계 면 자료가 있어서 `w_type="queen"`(경계나 꼭짓점이 닿는 상권을 이웃으로 봄)도 쓸 수 있다. 그러나 1,418개 상권으로 확인한 결과는 다음과 같다.
  - `queen`: 이웃이 하나도 없는 상권 87개(6%), 서로 끊어진 덩어리 163개, 평균 이웃 3.1개
  - `rook`: 이웃 없는 상권 92개
  - 상권이 서울 전역을 빈틈없이 덮지 않기 때문이다. 이웃이 없는 상권은 주변 영향을 따지는 전이 분석에서 다루기 어렵다.
  - **권장: `w_type="knn"`**(가장 가까운 k개 상권을 이웃으로 봄). 설계서의 원래 계획과 같다.
